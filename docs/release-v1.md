# 1.0.0 本机交付记录

## 交付范围

正式默认修复配置为 `v2`；`full` 等 v3 机制保留为显式实验配置。选择依据是 v2 在原四题的历史独立验收为 1/4、公开测试为 3/4，而 v3 `full` 的单次真实模型结果为 0/4；这只支持在当前证据下选择风险更低的默认流程，不证明 v2 对任意仓库或当前服务端模型具有稳定成功率。当前环境使用确定性模型完成网页全链路验收，不把它计入 qwen-plus 成绩。

可交付功能：固定 Git 提交与文件哈希的基线快照；Docker 中复现断言失败并分类环境错误；批准文件内、版本及位置绑定的局部编辑，兼容完整文件提交；语法预检、重复候选识别、调用/候选/时间预算；从原基线独立构建候选、确认测试身份和回归、导出 Git 补丁；本机网页、SQLite 任务队列、SSE 事件、协作式取消、测试日志与补丁/报告下载。原仓库不会被自动修改。架构见 [架构与验证规则](architecture.md)。

## 真实模型评测与风险

v1 原四题独立通过 0/4；v2 原四题 1/4，新增两道 boltons 题 2/2；v3 `full` 原四题 0/4、两道 more-itertools 跨项目题 0/2。v3 的负索引题反复在需求登记被拒，其他题出现无效结构化提交或截断，六题没有形成可执行候选。不同版本和单次采样不能证明某一机制的因果贡献，也不能将 boltons 结果推广到一般 Python 仓库。逐题调用、token、候选与失败证据见 [v2](evaluation-v2-20261011.md)及 [v3](evaluation-v3-20261012.md)报告；原始运行记录保持只读，不回写评分。

未解决：真实模型修复成功率低且波动大；v3 计划/提交接口难以可靠调用；复杂仓库及自定义依赖未做广泛验收；测试镜像需由部署者预先提供；服务只适用于本机单用户受控仓库；任务断点续跑、日志磁盘配额、多用户认证、公网隔离及恶意仓库防护未实现。原始测试通过仅证明该测试范围，仍需人工审核业务语义。
