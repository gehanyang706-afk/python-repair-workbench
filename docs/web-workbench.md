# 本机任务工作台

## 启动

```bash
cd /path/to/python-repair-workbench
.venv/bin/python -m pip install -r requirements-agent.lock
.venv/bin/python -m repair_workbench serve \
  --repo-root /path/to/approved-repositories \
  --image /your/local-test-image:tag \
  --env-file /path/to/private-model.env \
  --port 8765
```

打开 `http://127.0.0.1:8765`。Docker 必须运行，镜像必须已存在并包含目标项目的测试依赖。默认修复配置为 `v2`；`--profile full` 显式启用 v3 实验机制。部署前检查见 [本机部署](deployment.md)。

`--repo-root` 可重复指定，限制可导入的仓库范围。`--data-dir` 默认为 `runtime/workbench`；导入仓库与任务数据目录必须相互独立，不能包含对方。若要测试工作台仓库本身，应将数据目录改到仓库外。

前台启动使用 Ctrl+C 停止服务。页面关闭不会停止后台任务，应用退出则请求当前任务在操作边界取消，排队任务保留到下次启动。不提供系统开机自启动。

## 使用流程

1. 新建任务，填写 Git 仓库根目录和分支/提交，读取仓库。
2. 勾选批准修改的源文件，填写预期行为、失败表现和约束。测试文件不会出现在可修改清单中。
3. 加入队列。系统先固定提交 SHA，再执行快照、原始测试、Agent 诊断与候选验证。
4. 查看测试前后对比、候选诊断、事件时间线及每轮日志。
5. 通过验证后预览与下载补丁；工作台不会自动将补丁应用到原仓库。

任务读取当前提交的文件，未提交修改不参与测试。原始测试已通过、没有有效测试或出现依赖错误时，不调用模型进行修复。没有失败可修复与修复成功是不同结果。

## 架构与选择

页面使用同源 HTML/CSS/JavaScript，由 FastAPI 提供静态资源。当前页面规模无需单独前端构建或服务端渲染，部署时只有一个 Python 服务；后续界面复杂度增长时可在保持 API 的基础上替换前端。

- `api.py`：请求验证、仓库检查接口、任务/产物接口、SSE 事件流。
- `storage.py`：SQLite 任务表和事件表、事务领取、取消与终态写入。
- `service.py`：一个后台执行线程，调用已有快照、测试和 Agent 模块。
- `session.py`：通过事件回调向任务存储报告进度，通过取消回调检查停止请求。
- `static/`：任务表单、列表、阶段进度、结果对比、补丁与日志查看。

提交请求不会等待模型完成。SQLite 的短事务固定领取一个排队任务；后台线程执行耗时操作，HTTP 线程继续处理查看与取消。采用单执行器限制本机容器资源和模型并发，同一数据目录由进程锁防止第二个服务接管。当前队列最多 20 个未结束任务，列表展示最近 100 项。

## 状态与取消

任务状态：`queued → running → completed/error`；排队取消直接进入 `cancelled`；运行取消先进入 `cancelling`，当前操作结束并清理后进入 `cancelled`。

补丁结论保存在任务结果中，仍使用 `passed/failed/inconclusive`。任务执行完成不等于补丁通过；已通过补丁随后收到取消时，任务可显示取消，已有验证证据仍保留。

内置模型请求等待期间约每 50ms 检查取消，终止并回收本地请求进程；完整调用墙钟上限为 30 秒，清理可能额外耗时。无法确认清理时停止执行器并保留锁，不继续消费队列或宣称取消成功。容器操作仍为协作式取消，测试上限为请求中的 `test_timeout`（页面默认 30 秒、API 最大 60 秒），随后完成清理。取消不会安排下一次模型调用，但不能保证供应商停止已接收的远端推理，已发出的调用可能计费。

## 持久化与重启

默认数据布局：

```text
runtime/workbench/
  tasks.sqlite              # 任务与有序事件
  worker.lock               # 单执行器进程锁
  runs/<task-id>/
    baseline/               # 固定提交与原始测试
    agent/
      result.json
      events.jsonl
      attempt-NN/
```

页面刷新后从 SQLite 读取记录。SSE 事件携带递增 ID，断线后通过 `Last-Event-ID` 续读，终态事件和状态在同一事务提交。该机制用于进度显示，不承担任务执行驱动。

服务启动时将遗留的 `running/cancelling` 标为 `interrupted`，不会自动重新调用模型；排队任务继续等待领取。已完成任务和产物保留。没有实现 LangGraph checkpoint 续跑、原执行进程恢复、容器崩溃遗留自动清理或严格 exactly-once 语义。

## 本机访问边界

命令行入口固定监听 `127.0.0.1`，没有公开部署或多用户认证。修改请求要求自定义请求头，并检查浏览器 Origin；不开放跨域访问。仓库真实路径必须位于启动时配置的范围，产物只通过固定任务目录读取。服务端读取模型密钥，页面不能提交或查看密钥配置。诊断、日志与补丁作为文本展示，不解释其中的 HTML。

这些措施用于本机单用户工作流，不代表适合暴露到局域网或公网，也不使被测代码成为可信代码。完整恶意代码隔离、日志磁盘配额、数据库迁移、多执行器、任务断点续跑及真实复杂仓库评测仍未完成。
