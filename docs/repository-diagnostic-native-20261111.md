**真实仓库原生诊断图与独立执行入口（2026-11-11）**

在[独立性能验收与SWE公开复现](repository-performance-and-public-probes-20261111.md)基础上，真实仓库接入原生Deep Agents工具循环。保留现有UGC入口与MCP协议。新增入口仅由应用显式创建，不改变默认修复流程。本轮没有供应商模型请求。

**公开准备与工具循环。** `prepare_repository_diagnostic_baseline` 从冻结快照建立新副本，重新运行精确原测试。可信准备器用完整WorkloadSpec核对测试身份、原有XFAIL/XPASS、镜像、清理和源码；向 `RepositoryDiagnosticSession` 只交付公开投影及受限资格回执。原始仓库、已有快照和报告均保留。会话再核对原套件、原报告、测试状态映射及基线身份，不要求真实仓库伪装成UGC工作负载。

真实仓库复用现有 `create_deep_agent`、状态后端、虚拟文件、待办和模型预算包装。根据症状读取源码、记录和更新假设，选择 `run_probe(probe, case_id, hypothesis_id)`。工具只接受事先登记的公开输入，模型不能提交任意执行命令、worker或最终工作负载。可选受控复现仍只在原基线执行，输出始终保留 `model_program_output`。

公开CPU探针使用cProfile和同一注册业务入口，最多保存15个热点、初始摘要3个，路径仅为仓库相对路径或外部文件名；它不充当最终无profiler计时。内存及基准复用已有注册测量worker，保持Python可追踪分配口径。每次物理探针仅挂载当前公开job、已登记worker与冻结源码，无网络、1CPU/256MiB/64进程，限制时间和输出并确认清理。物理派发、缓存命中、源文件读取和报告回查分别记账。

报告按快照、公开契约、输入、采样和实现绑定，长报告落盘后通过证据引用分页读取。重复探针可复用同一报告，仍计根工具调用；缓存和回查前保留身份校验。执行错误、输入漂移或清理未知不能成为可复用证据。清理状态在启动前置为待确认，缺少真实回执不能推定已清理。

**封存与图外评分。** 首次有效补丁通过版本、权限、唯一原文和语法检查后，从基线独立重建并封存；保持原始UTF-8字节与候选散列。`final-submission.json` 绑定公开工作负载、基线、候选和补丁，状态为`submitted`，此后会话阻断模型与工具。`no_change`与`insufficient_evidence`也封存并结束，作为待审提议。

应用入口 `run_repository_diagnostic_task` 接收显式模型对象；它不加载密钥，也不授权新的模型调用。等Agent退出、复现和探针清理确认后，才将完整契约交给独立Python评分进程。评分端使用同一原测试资源策略，从原基线再次重建候选，然后运行最终输入ABBA。CLI进程使用白名单环境，不传递模型或供应商密钥。提交/补丁散列漂移、评分进程清理未确认、运行停止和缺少可用评分均保留，隐藏反馈不会触发第二次模型调用。

真实批次将通过应用侧`identity_check`和`on_final_submission`接入冻结检查及独立评分时钟；高频等待使用轻量控制。当前入口还未包装成获批真实批次。已知候选、脚本策略与本地工程测试均不能替代同模型同预算的真实效果对照。

**调度口径与适用范围。** 固定预诊断依序运行CPU、内存、基准，再进入同一个模型工具循环；按需组从相同公开起点自行选择。预跑调用计入共享预算。当前首版明确支持本地执行，拒绝真实仓库模式的MCP、Skills、委派或并发参数；原UGC中相应能力保留。最终输入与报告不进入本地/远程Agent证据目录。

此版本只支持注册的SQL格式化及迭代器切片输入，首次封存前不试跑候选；健康对照独立评分、真实仓库MCP报告协议、更多未暴露任务与正式F0/A1模型对照仍待完成。性能噪声导致的不可判定继续保留，不能为通过修改阈值或重复选择有利测量。

**真实仓库离线链路控制。** 在完整的已见sqlparse开发仓库中，用确定性脚本和已知上游源差异验证一次自适应路径、一次固定路径。应用与依赖指纹在开始前冻结，80个源码/实现绑定文件逐字节归档。两条路径的公开工具Schema一致，使用同一公开工作负载、权限和资源策略；脚本动作不同，因此这些结果只用于证明各路径执行顺序和评分隔离，不构成对照效果估计。
