# 简化编辑接口实验配置

`simple_edit` 是独立的工具可用性实验配置；`repair`、`serve` 的默认配置仍为 `v2`。本配置不启用 v3 的强制需求表单或上下文预载，也不改变模型、调用次数、候选次数、超时、测试和独立验收规则。提示词保留 v2 的共同诊断要求，只替换编辑工具说明。历史 v1/v2/v3 结果保持原样，不能将本配置的机制测试当作真实模型成绩。

## 调用链与权限

Agent 读取失败日志和基线源码 → 本配置的 `read_source` 直接返回无行号原文及不透明 `source_ref` → Agent 用 `submit_ref_edits` 提交一个或多个 `{source_ref, old_text, new_text}` 和诊断 → 应用从 Session 内部引用表解析基线、路径、文件版本和已返回的读取范围 → 复用原有精确原文匹配、唯一性、重叠检查、候选物化、语法预检、重复候选检测和 Docker 原测试验证 → 人工审核补丁。每个候选仍从原始基线生成，旧的 `submit_edits` 和完整文件提交接口在其他配置中保持可用。

引用只在当前 Session 内有效；Session 结束、快照被改动、引用来自其他 Session、原文不在返回范围内、文件不在批准修改范围内，均拒绝。应用不模糊匹配、不根据参数错误猜测代码。多个编辑先整体校验；任一项不合法便不建立候选目录。`old_text` 必须在整个文件中唯一，即使在当前读取片段中只出现一次也不例外。

工具 Schema 使用嵌套的 `RefEdit` 类型；向模型提供的编辑字段只有 `source_ref`、`old_text`、`new_text`。工具调用形状事件只记录字段名、类型和条数，不记录源码、引用值或模型参数。Schema 拒绝、JSON 解析失败、截断输出、业务预检拒绝和供应商异常分别记录。无效调用最多恢复两次，且与正常调用共享原模型预算；连续相同错误停止。认证或欠费错误不作为普通编辑错误重试。截断输出不会被拼接成补丁。

## 计数口径

`result.json` 中的 `submission_counts` 保留五个原始计数：`requests` 为进入提交方法并占用候选额度的请求；`schema_rejections` 为工具参数解析或类型错误，不占候选额度；`preflight_rejections` 为进入候选流程后被版本、权限、匹配、重复或语法检查拒绝的请求；`materialized` 为成功建立候选目录的次数，包括随后因重复或语法错误被拒绝的候选；`docker_verifications` 为实际调用 Docker 验证的次数。这些数不能简单相加为总候选数。旧历史记录没有同口径字段，前后比较需要从事件重建共同分母。

## 验证状态

确定性回放覆盖真实读取引用、Schema 字段类型、跨 Session 和结束后引用、读取范围、版本篡改、重复原文、修改重叠、路径越界、无效 JSON 恢复、重复 Schema 错误终止、截断输出、认证失败，以及源码和参数不进入安全事件日志。Docker 集成测试使用本地已有镜像，确认有效编辑进入隔离验证并产生补丁，原仓库不变。

2026-10-12 已完成批准的[两题成对真实模型评测](evaluation-simple-edit-20261012.md)，合计 42/48 次模型调用。两次简化接口运行均首个候选公开通过；boltons 空转换题独立漏修，more-itertools validator 题独立通过。两次 v2 对照均在读取阶段耗尽预算，无候选；不代表旧编辑工具本身被验证为失效。本轮没有 Schema 或语法拒绝，恢复机制仍只有确定性测试证据，结果不能证明稳定或广泛提升。
