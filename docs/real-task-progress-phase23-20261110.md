**受控复现程序。** `ReproductionWorkspace` 提供 `propose_reproducer` / `run_reproducer` Python接口。程序引用绑定基线快照、代码、不可变镜像和执行包装版本；代码仅在Docker中运行，不由宿主导入。复现程序不写入目标仓库或原测试，运行只挂载当前快照、当前程序和只读包装器，不挂评分目录、密钥或Docker控制接口。

执行具有程序数/运行数、墙钟、CPU、内存、进程、临时文件与输出字节限制；输出边读边截断，避免仅在落盘后才发现超限。记录提出的程序、原始观察、预算准入、结果和清理。主诊断Agent现可通过应用侧 `--reproduction` 显式开放两个工具，默认关闭；它们共享根工具次数、取消和截止时间，不能成为只读Investigator的额外工具。该主图仍只接受原UGC工作负载，不能据此宣称任意真实仓库诊断入口已经适配。

程序的输出标记为 `model_program_output`。正常结束仅代表执行完成；它不能自行确认业务异常、正确性或优化成功。真正的故障判断和最终验收仍须来自可信契约与独立测量。受控项目执行也不等于面向恶意代码的完备安全证明。

实际Docker检查覆盖正常执行、目标源码只读、输出洪泛截断与超时，四种运行都确认清理；两个完整真实性能仓库也通过操作方编写的复现程序执行。这仍是工具接线验证，没有供应商模型调用。首次集成检查因测试程序误用夹具函数名失败，原日志保留；修正后在新日志验证。
