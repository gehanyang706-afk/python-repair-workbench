# 诊断重复动作与停滞停止

诊断工具循环在发送下一次模型请求前检查刚完成的工具轮。相同源码读取会产生新的编辑和证据引用，引用变化本身不再被当作新观察。原 Bug 修复流程不启用这项策略；诊断的 adaptive 与 fixed 两种模式使用同一规则，固定策略的预跑测量不计入重复轮。

## 判断范围

比较只使用当前模型请求中仍可见、能配对到真实调用的工具结果。指纹绑定基线、工作负载、工具、策略版本、规范化参数及稳定观察内容；不包含原始源码或日志正文。源码版本和内容仍参与计算，随机引用、剩余额度、耗时、假设编号和 revision 不代表进展。

不同源码范围、新搜索结果（包括空搜索等负证据）、新诊断观察、不同候选及复验结果均可打断连续重复。只改写假设或待办不能证明取得了新观察。若旧结果已不在当前消息窗口中，不凭历史缓存处罚重新读取。

连续三轮可确定重复后，应用注入一次简短提示，要求在原预算内换调查方式、提交已有候选或提出证据不足结论。下一轮仍重复时，在预留和发送下一次模型请求前停止。提示没有独立的调用额度，也不自动运行新实验。

该规则识别有限工具的确定性重复，不计算信息增益，也不判断推理是否正确。首次空搜索和否定证据有诊断价值；可见结果相同也不意味着该动作在所有上下文中都无价值，因此保留回查及一次调整机会。无法可靠解析的结果继续由原工具恢复与总预算约束。

## 主子任务与资源

主任务以 `diagnostic_no_progress` 保持停止状态，之后不能继续实验或提交候选。根取消及截止时间优先检查。investigator 使用独立的轮次状态，局部停滞通过原委派边界返回主任务；每次新委派重置局部记录，不重置根预算或根期限。默认较小的子请求配额也可能先耗尽，停滞保护不会增加配额。

合法调查回执提供一次恢复机会。应用按父模型轮次、具体工具调用ID的哈希、返回内容哈希和真实调用记录绑定回执，避免同轮多次委派被子请求累计次数混淆。调查建议仍需主 Agent 回查，不能因它打断了重复计数就认定根因正确。

`progress/main.json` 与按委派编号保存的调查记录包含稳定指纹、观察轮次、重复计数、提示及停止状态。事件流保存相应摘要，最终结果保存索引与计数。源码、完整工具报告及候选的原始证据继续保存在原目录，不由进度记录替代。

## 验证边界

测试使用确定性模型、真实 Deep Agents 工具循环和合成回执，不请求模型 API。最终执行数量与原始日志记录在[交付清单](diagnostic-mcp-delivery-20261031.json)。这些检查证明重复检测、提示、恢复和停止路径，不能写成真实模型 Token 降低、无效探索比例下降或成功率提升。

