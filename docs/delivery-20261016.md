## 完成内容

- Schema/JSON 错误同时保留兼容总数、具体工具和类别统计，区分编辑、读取/搜索、分析、框架与未知工具。分母是模型提议调用数，包括参数无效的调用，不等于 Session 实际执行次数；读取拒绝不能写成编辑提交失败。原候选计数与评分规则不变。
- 超时按连接 5 秒、读取 30 秒、调用墙钟 30 秒及 Session 截止分别记录；墙钟先到时记录 `model_call_timeout`，不根据等待时间猜测读取超时。失败请求标记用量缺失，取消要确认进程回收，不能保证远端推理停止或退款。
- 固定参考 Dockerfile、独立测试依赖与工作台锁文件；新虚拟环境安装、安装包启动、静态资源和关闭验证通过。镜像不内置目标项目代码，不承诺兼容任意项目。
- 无密钥 CI 配置包含标准库核心、完整 Docker 回归、工具与请求契约、数据集哈希、安装包及新增任务资格核验。只有本地等价检查通过，远端尚未运行。
- 提供[最短演示](demo.md)、[架构与成功/失败案例](showcase.md)、脱敏证据和固定默认配置。

## 当前实际流程

用户提交仓库修订、任务与批准范围 → FastAPI / CLI 校验 → SQLite 串行队列固定提交 → Git 快照 → Docker 复现公开失败 → 单 Agent 通过受控请求进程调用模型 → 读取基线、在预算内提交修改 → 权限、版本、精确匹配、原子性、重复与语法预检 → 从原基线独立重建并执行 Docker 原测试 → 展示候选、停止原因、验证范围和用量 → 人工审核并下载补丁。

simple 系列的 source_ref 编辑保留；`simple_context` / `simple_review` 可独立开启失败上下文与非阻断 diff 风险，`simple_full` 同时开启。交付默认 `v2` 不启用这些实验机制。独立验收仅属于评测器，官方补丁和隐藏测试不进入 Agent 基线。架构没有增加多 Agent、向量库或分布式系统。

## 默认选择和限制

保守固定 `v2`，详见[冻结配置](default-configuration.json)。依据是既有工程调用链的完整回归和缺乏推广新机制的正面证据，而不是四配置比较获胜。旧 v2 成绩不能证明当前严格客户端的修复稳定性。回退优先使用冻结源码与 `--profile v2`，保留已修复的权限、请求生命周期和验证边界；历史标签用于历史复现，其超时行为不同。

预检第一题在缩小的 3 次上限内读取成功，第二题返回无工具的无关文本。没有频繁超时证据，不据此放宽 30 秒限制；异常文本根因尚未确认，也不能归因于换 Key。完整矩阵没有完成，因此上下文和审查各自的实际收益仍未知。

其他限制包括：单用户、本机受控仓库、有限依赖、原始测试覆盖不足、JUnit 来自被测进程、静态定位无法覆盖所有动态调用、缺少真正崩溃续跑。请求进程控制实测主机是 macOS，Linux 主机与远端 CI 未验收，Windows 不支持当前 POSIX 实现。产品应称为有限范围的修复工作台，不称为稳定自动修复系统。

## 他人如何复现

使用本轮源码包，按[演示路径](demo.md)安装锁定依赖、构建参考镜像、复制已有折扣边界夹具，再从网页提交。无密钥 HTTP/Docker 链路验收使用确定性模型，真实演示提交会调用付费模型，成功与失败均应如实展示。新增仓库级资格核验按[任务说明](../benchmarks/delivery-heldout-v1/README.md)执行，不需要 API Key。

源码包包含源码、测试、固定任务、许可证和文档，不包含 `.git`、密钥、个人路径、虚拟环境或完整运行目录；安装包只含工作台模块和网页资源。原始运行证据在本机保留。公开材料中不引用未完成的远端 CI 或不存在的生产用户。
